# Машины состояний в Lockpick Puzzle

## Как устроен код

| Файл | За что отвечает |
|---|---|
| [State.lua](content/Scripts/Lockpick/State.lua) | Создаёт описания состояний с таймером и без таймера. |
| [StateMachine.lua](content/Scripts/Lockpick/StateMachine.lua) | Хранит текущее состояние, отсчитывает время и сообщает о переходах. |
| [GameStates.lua](content/Scripts/Lockpick/GameStates.lua) | Определяет состояния игры `PLAYING` и `RESULTS`. |
| [RoundStates.lua](content/Scripts/Lockpick/RoundStates.lua) | Определяет фазы раунда, их длительность и действия по завершении. |
| [GameFlow.lua](content/Scripts/Lockpick/GameFlow.lua) | Запускает раунд, обрабатывает его результат и перезапуск. |
| [Round.lua](content/Scripts/Lockpick/Round.lua) | Применяет правила головоломки, хранит очередь карт и управляет фазами раунда. |

`GameFlow` и `Round` создают отдельные экземпляры `StateMachine`. У каждого экземпляра свои `currentState` и `elapsed`. Модули `GameStates` и `RoundStates` экспортируют `Id` с именованными строковыми константами и `definitions` с описаниями состояний. Например, код использует `RoundStates.Id.SHOCK`, а в журнале появляется строка `shock`.

## State.lua и StateMachine.lua

```lua
-- Раунд ожидает, пока игрок выберет карту.
[Id.READY] = State.untimed(),

-- Через 0,13 секунды правила раунда определят результат контакта.
[Id.STRIKE] = State.timed(0.13, function(round) round:impact() end),
```

- `StateMachine.new(states, owner, onTransition)` принимает таблицу описаний, владельца машины и необязательную функцию для уведомлений о переходах. Начальное состояние задаёт вызывающий код через `transitionTo(id)`.
- `transitionTo(id)` проверяет наличие описания состояния, устанавливает его и обнуляет таймер. Повторный вход в то же состояние также обнуляет таймер. `onTransition(previous, current)` вызывается только при смене идентификатора. При первом входе `previous` равен `nil`.
- `isTimed()` проверяет, есть ли у текущего состояния длительность. Состояние без таймера ждёт явного перехода.
- `update(dt)` принимает время кадра в секундах. Когда таймер истекает, машина вызывает `complete(owner)`. Следующее состояние выбирает эта функция.
- `update(dt)` возвращает идентификатор обработанной фазы, прогресс от 0 до 1 и накопленное время. Если за этот кадр произошёл переход, возвращается прежняя фаза, чтобы `LockView` мог отрисовать её финальное положение. Остаток времени кадра не переносится. Новая фаза начнёт отсчёт на следующем кадре.

## Состояния игры в GameFlow

`PLAYING` и `RESULTS` работают без таймеров. При запуске `GameFlow` входит в `PLAYING` и создаёт раунд. Когда раунд сообщает `won` или `lost` после завершения анимации, `GameFlow:roundFinished()` переводит игру в `RESULTS`. Повторная попытка возвращает игру в `PLAYING` и загружает начальные данные того же уровня. Обычный перезапуск доступен и во время раунда.

## Фазы раунда в RoundStates

| Фаза | Длительность | Что происходит дальше |
|---|---:|---|
| `READY` | Без таймера | Выбор карты запускает `TURN`. |
| `TURN` | 0,30 с | После поворота начинается `STRIKE`. |
| `STRIKE` | 0,13 с | При контакте `Round:impact()` расходует попытку. Пустое гнездо становится занятым, затем начинается `RECOIL`. Если гнездо уже занято, начинается `SHOCK`. |
| `RECOIL` | 0,13 с | После последней успешной попытки начинается `OPEN`. Если есть карта в очереди, начинается `TURN`. Иначе раунд возвращается в `READY`. |
| `SHOCK` | 0,42 с | Проигрыш сопровождается вспышкой у точки контакта, затем начинается `DROP`. |
| `DROP` | 0,35 с | Отмычка падает. Раунд записывает `lost` и переходит в `FINISHED`. |
| `OPEN` | 0,70 с | Дверь открывается. Раунд записывает `won` и переходит в `FINISHED`. |
| `FINISHED` | Без таймера | Раунд завершён. Игрок может перезапустить уровень. |

При запуске и перезапуске раунд сразу входит в `STRIKE`. После установки первого штифта и завершения `RECOIL` раунд берёт следующую карту из очереди или ждёт ввода в `READY`.

## Связь с SRI и журнал

[Lockpick.lua](content/Scripts/Lockpick.lua) создаёт объекты в `OnStart`. В `OnUpdate` он сначала проверяет клавиатуру. Если активна фаза с таймером, скрипт обновляет раунд и передаёт фазу с прогрессом в `LockView`. HUD обновляется при изменении данных, которые он показывает. Щелчки по кнопкам приходят через callbacks RmlUi.

Для поиска в журнале используйте `[LOCKPICK][GAME]` для состояний игры и `[LOCKPICK][ROUND]` для фаз раунда.

```text
[LOCKPICK][GAME] playing -> results | level=storage outcome=won
[LOCKPICK][ROUND] strike -> shock | level=storage
```
